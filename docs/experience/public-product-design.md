# 项目读本生成网站 · 2026-09-28

本轮以用户提交的总目标为已确认设计：主入口始终是上传自己的项目，三本现有书只证明成品质量。取代旧进度中的“先体验三本书，再导入”。现有未提交工作继续保留。

## 页面与状态

- 官网：浅纸面、墨字、粘土色主动作。左侧一句“把你的项目，读成一本书。”与“把我的项目变成书”；旁边明确 GitHub / 本地文件夹。右侧源码、目录、书页组合表达转化，标注为过程示意，不冒充真实生成。下方真实案例取已有三本书、真实预览接口中的目录与摘录。
- 上传：同一对话框中选来源、确认名称、选择阅读目的（快速理解 / 深入机制 / 接手修改），再提交；错误保留输入。目录可拖入与选择，文件读取即有反馈。
- 生成：文件归集、内容组织、书页形成、封面完成构成视觉母题；阶段必须受服务端实际字段驱动。没有流式产物时只能显示正在撰写，不显示虚构章节或百分比。任务持久保存；可离开、重连、重试。仍在生成对话框时完成则关闭并进入书架，新书突出；已离开只通知。
- 书架：与官网用 URL hash 切换（#library），保留独立个人空间语义。三列分行错位叠放，封面右侧装饰边缘可重叠，标题与默认选择区域不被盖住。停留约 180ms 才展开原位只读预览；移入预览保持；离开约 160ms 归位。邻书固定，快速划过不抖动。窄屏减少重叠，用明确预览按钮；键盘聚焦预览，Enter 打开。
- 开书：记录书架过滤、查询与滚动位置；以当前封面为起点放大承接，加载期间保持书名与对应配色。慢响应可重试/取消；不重复导航。正文加载后工具退下。返回恢复位置并指出刚读过的书。

## 工程边界

- 现有模型 API、源码不可变快照、原书正文、旁注与探索契约保持。
- 官网与书架复用书目数据和导入表单；新的视觉模块与 shelf.js 状态编排解耦。
- 阅读目的作为枚举持久写入 project.json，进入生成提示词；失败后重试仍保留。
- preview GET 只读，不生成、不更新阅读记录；真实摘要缺失时明确显示缺失。
- 本轮不重生成三本现有书。隔离预览使用它们的副本，正式数据不用于自动化写入测试。
- 保留本机单人模式，新增独立的公共服务模式：GitHub 身份对应独立的项目、源码快照、旁注、探索与额度记录；私有书与 API 依会话鉴权。页面请求绑定打开页面时的账户，跨标签换号后拒绝旧页面读写其他账户。浏览器草稿和阅读记录也按账户隔离。
- 用户已确认“GitHub 登录后生成，访客可看案例”。访客仅访问三本明确的公开读本；生成及个人资料归属需登录。公开案例本轮只读，不调用模型、不写旁注，也不开放未完成脱敏的源码快照。账户面板展示真实生成额度与 AI 使用次数；本轮不接支付，不把次数描述为付费余额。
- 先在本地公共服务模式完成访客、账户隔离、真实状态、故障恢复与浏览器验收，再接真实域名、GitHub OAuth 回调和公网反向代理。当前验收不等同于已部署上线；外部登录与域名验收在配置就绪后进行。

## 实施选择

采用现有原生 JS/Node 增量改造：保留已验证的源码、阅读和导入链路，新增官网、叠书和导航模块。全站框架重写会扩大兼容风险；纯静态展示无法满足真实导入与恢复，因此均不采用。

## 验收

三本真实书：默认标题可辨、快速经过/停留/移入预览稳定、点击正确、返回位置恢复。受控隔离数据：生成中刷新、失败重试、失联重连、新书入架、阅读目的传递。多书/长标题/窄屏/键盘/减少动效：不溢出、不误点、不重排。自动检查和浏览器观察分别记录，视觉喜好与真机原生文件夹操作由用户验收。
