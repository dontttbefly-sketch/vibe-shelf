## 当前产品约定

主线是官网 → 上传自己的项目 → 选择阅读目的 → 真实生成状态 → 新书进入个人书架 → 预览 → 阅读。三本现有书作为公开成品案例。用户明确选择 GitHub 登录后生成、访客看案例，以及先验收本地公共模式，再确定域名。

浏览器验收发现并修复原生 submit 的再入问题：异步账户门禁在原提交事件内 requestSubmit 会被浏览器忽略。已确认允许时同步放行，尚未确认时在下一任务重放。修复后真实按钮提交成功。单纯 mock 的事件模型不能替代该浏览器证据。

`setInputFiles` 目录方式未提供任何文件；后续明确使用 File/DataTransfer 样本，没有将其记为原生文件夹选择器通过。`waitForFunction` 在公共页面曾超时，后续按实际 DOM/API 状态回读；一次转场截图捕获超时，但随后同页的导航、书名及返回焦点已确认。工具超时与应用结果分开记录。
