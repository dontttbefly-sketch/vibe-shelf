# 把任何项目变成一本「代码教学书」——通用 AI 指令

> **用法**：把本文件全部内容交给你的 AI 编程工具（WorkBuddy / Claude Code / Cursor 等），并把开头【】里的三处替换成你的实际情况。AI 写完后，回到仓库 README 的「第 3 步」把书装进书架。

---

把位于【项目路径】的项目源码，编写成一本**自包含的 HTML 代码教学书**。我【熟悉/不熟悉】编程，请用【通俗直白/专业】的语言。这本书的目的是让我**完全掌握这个项目的代码知识体系**。读者会慢慢读，你分批交付：一次写 3~4 章，写完告诉我可以读了，我喊继续再写下一段。

## 核心教学法（不可更改）

不是「按文件顺序讲代码」，而是**从可见结果倒推代码**：

```
我在页面上看到的 → 哪一段代码做出来的 → 这背后叫什么名字 → 它在哪会失效
```

每章固定五段，顺序不可调：

| 段 | 内容 | 为什么必须有 |
|---|---|---|
| 你看到的 | 先描述效果/现象，让我有画面 | 建立"你要解释的是这个"的锚点 |
| 代码 | 贴真实源码，不简化掉关键细节 | 可信度来自原样引用 |
| 知识点 | 这行代码的通用概念叫什么 | 让我能迁移到别的项目 |
| **局限** | 这个写法在哪会顶不住 | 教程最常跳过、但对读者价值最高的一段 |
| 小结 | 3~5 条要点 | 便于回看 |

**「局限」的写法**：不要泛泛说"性能可能有问题"。给出可验证的具体事实，例如：
- 统计得出「某属性出现 0 次」→ 指出这是个真实遗漏
- 指出项目内部的自相矛盾（某处违反了项目自己的规范）
- 说清"如果项目规模涨 10 倍，这里会怎样"
- 给出工业界的替代方案，并说明它解决了什么问题

引用行号（`app.js:762`）能大幅提升可信度——但**必须先用搜索验证行号真实存在**，不要凭印象写。

## 阶段 1 · 调研（不能跳）

1. 摸清规模：统计每个文件行数、目录结构。
2. 读完核心逻辑文件，大文件（>2000 行）只读关键函数。
3. 样式文件用搜索定位关键锚点（类名、`:root` 变量），不要通读几千行 CSS。
4. **验证每一个准备写进书里的断言**：用搜索计数验证"出现 N 次""0 次""只用了一次"。这一步决定这本书是"可信"还是"听起来对"。
5. 主动找两类硬证据，它们比任何泛泛评论都有价值：
   - **死代码**：把代码里的选择器逐个去 HTML/CSS 里验证是否匹配得到元素。匹配 0 个 = 一段从没跑过的代码，而且控制台零报错——这是最好的教材。
   - **反向异常**：某属性"有读取、没有生产"、某函数"被调用但查不到目标"。这类行是 bug 的指纹，一眼就能讲透。

## 阶段 2 · 规划章节

**按"页面上可见的区块"切章，不要按文件切。** 参考骨架（约 20 章）：

- 第一篇 地基：文件地图 / 设计令牌与全局重置 / 语义化
- 第二篇 结构：两种钩子（class vs data-*）/ 无障碍 / 表单与按钮
- 第三篇 外观：CSS 三根支柱 / 用代码画图形 / CSS 变量做桥 / 响应式
- 第四篇 行为：结构总览 / 数据层 / 状态层 / 渲染循环 / 事件委托 / 各业务模块
- 第五篇 边界：架构复盘 / 局限与前后端边界
- 附录：术语表 / 属性全表 / 函数索引 / 自查清单

目录里先把未写的章节也列出来并标注「待写」——让读者看见全貌（全部写完后去掉标记）。像"属性全表""函数索引"这种长附录**必须用脚本生成**，不要手写：审计脚本把结果写成 TSV，再用脚本读 TSV 拼进 HTML，保证数字与正文同源。

## 阶段 3 · 生成 HTML（⭐ 必须遵守书架结构约定）

**单文件自包含 HTML，不依赖任何 CDN，离线可看。** 为了能被 vibe-shelf 的旁注系统接管，结构必须满足：

| 约定 | 写法 |
|---|---|
| 样式全部内联 | 所有 CSS 放在 `<head>` 的**一个** `<style>` 里 |
| 阅读进度条 | `<body>` 的第一个元素：`<div class="progress"></div>`（细条，fixed 顶部） |
| 正文容器 | `<main class="book-main">` |
| 每一章 | `<section class="chapter" id="ch1">` … `</section>`，章内大标题用 `<h2>` |
| 章内元素 | 只用 `p / li / h3 / h4 / pre / table`（旁注系统按这些元素落锚） |
| 结尾 | `</main>` 后放 `<footer>`，然后**一个** `<script>`（下面配方 5 的三个交互），`</body>` 结束 |
| 无外部资源 | 不引 CDN、不引外部字体；图标用行内 SVG |

## 阶段 4 · 校验（交付前必做）

1. 标签配对校验（写个小脚本数 `<section>`/`<table>`/`<pre>` 开闭是否一致）。
2. 代码高亮逻辑验证：抽一个代码块手动走一遍替换规则，确认不乱码。
3. 所有 `<pre>` 里的 `<` `>` `&` 必须转义成 `&lt;` `&gt;` `&amp;`——**用脚本批量检查**：抽出所有 `<pre><code>` 内容，搜 `<(?=[a-zA-Z\/])`，命中即漏。
4. 交付后告诉我可以读了。

## 技术配方

### 配方 1 · 无依赖的轻量代码高亮

只给注释和字符串上色就足够"看起来专业"，且零风险：

```js
document.querySelectorAll("pre code").forEach((block) => {
  let text = block.textContent
    .replace(/&/g, "&amp;").replace(/</g, "&lt;").replace(/>/g, "&gt;");
  text = text.replace(
    /(\/\/[^\n]*|\/\*[\s\S]*?\*\/|&lt;!--[\s\S]*?--&gt;)|("[^"\n]*"|'[^'\n]*')/g,
    (m, c, s) => (s ? '<span class="c-st">' + s + "</span>" : '<span class="c-cm">' + m + "</span>")
  );
  block.innerHTML = text;
});
```

**必须单遍扫描（一个正则 + 分支）**。先替换注释、再替换字符串的话，第二步会匹配到第一步插入的 `<span class="c-st">` 里的引号，输出彻底坏掉。

### 配方 2 · 代码块样式

浅底 + 左侧彩色条，比深底更适合与正文混排：

```css
pre { background: #fffdf7; border: 1px solid var(--line);
      border-left: 3px solid var(--accent); border-radius: 8px;
      padding: 16px 18px; overflow-x: auto; }
pre code { white-space: pre; font-size: 12.5px; line-height: 1.72; }
.c-cm { color: #849690; font-style: italic; }  /* 注释：灰绿斜体 */
.c-st { color: #a8471f; }                       /* 字符串：棕红 */
```

### 配方 3 · 表格列宽

不要用 `table-layout: fixed` + 固定百分比列宽——形态多样的表格里长文本列会被挤成一字一行。交给浏览器自动分配（`table-layout: auto`），只对"确定很短"的首列加 `white-space: nowrap` 工具类。**绝对不要写 `th:first-child { width: 1% }` 而不配 nowrap**——它会把 `HTML` 竖成 H/T/M/L。

### 配方 4 · 配色与源项目呼应

教学书用**被讲解项目自己的设计令牌**（读它的 `:root`，把主色/底色/强调色原样搬进书的 CSS）——读者会注意到"书和站点是一套颜色"，这本身就是个教学细节。

### 配方 5 · 三个必有的交互

| 功能 | 实现 |
|---|---|
| 顶部阅读进度条 | `scroll` 事件算 `scrollY / (scrollHeight - innerHeight)` |
| 目录高亮当前章 | `IntersectionObserver`，`rootMargin: "-72px 0px -70% 0px"` |
| 章节锚点不遮标题 | `.chapter { scroll-margin-top: 90px }` |

## 踩坑清单（前人翻过的车，直接绕开）

| 坑 | 解法 |
|---|---|
| 高亮分两遍替换 | 改单遍扫描（配方 1） |
| `table-layout: fixed` + 百分比列宽 | 改 `auto` + nowrap 工具类（配方 3） |
| `<pre>` 里的 HTML 未转义 | 批量脚本检查 `&lt;` 转义（阶段 4） |
| 拼接脚本重跑导致章节重复 | 插入前先断言目标 id 尚不存在，而不是断言锚点唯一 |
| 声称"N 次""0 次"却没验证 | 一律搜索实测计数，先手工验证 2~3 个样本再信全量数字 |
| 统计属性名不带边界 | `data-play` 会误中 `data-play-product`，正则要加 `(?![a-z0-9-])` |
| 分批交付时章节顺序错乱 | 合并后把章节标题按顺序打印出来核对一遍 |

## 语气与表达

- 用**第二人称**："你看到的""你现在会……"
- 每章开头给一个一句话目标（"读完这章你会知道……"）
- 讲抽象概念用日常类比，但不要幼稚化
- 有观点就说出来（"这个用法几乎可以当标准答案来抄"）
- 避免"很简单""显然"——读者卡住时会觉得自己笨
- 正文里不堆 emoji；用带颜色的小标签块区分段落类型

---

写完的书是一个单文件 HTML。回到 vibe-shelf 仓库根目录执行：

```bash
node build.mjs <书文件路径> --book myproject --title "我的项目 · 代码教学书"
node server.mjs
```

打开 http://localhost:8899 ，选中书里任何一句话就能让 AI 补旁注了。
