# 从「一本书」到「书架 + 旁注」

当用户读完第一本书、想要一个**能沉淀多本书、能改、能挂笔记**的平台时读这一份。
下面每条都标了状态：**✅ 实测** / **⚠️ 设计未落地**。

---

## 1. 核心判断：外观和格式是解耦的

用户第一个担心通常是"**换成 Markdown 是不是就不好看了**"。答案是：不会，**因为好看来自 CSS，不来自 HTML 还是 Markdown**。

已经用两步实证过（结论可信，可直接复用这个方法说服用户）：

### ① 文本层比对（证明内容没丢）

把原书章节 HTML 和"Markdown 渲染结果"都抽成纯文本，去掉所有空白字符后逐字比对：

```js
const squash = (s) => s.replace(/[\s\u3000]/g, "");
const sa = squash(textOf(origHtml)), sb = squash(textOf(renderedHtml));
let pre = 0;
while (pre < sa.length && pre < sb.length && sa[pre] === sb[pre]) pre++;
console.log(sa.length, sb.length, "首个分歧在 " + pre);
```

实测第 4 章：**原文 4530 / 渲染 4530，差 0，从头 4530 字符完全相同**。

用"首尾公共前缀法"定位分歧点非常有效 —— 它会直接打印出分歧处的上下文，一眼看出问题出在哪个语法上（见 §3 踩坑）。

### ② 视觉层比对（证明外观没变）

同一个页面上放两个 `<main>`，一个渲染原 HTML、一个渲染 Markdown 结果，同一套 CSS。
headless Chrome 分别截图，再逐像素比对：

```bash
# 只显示其中一个，另一个用 hidden 隐藏（不要去改 CSS 的 display）
```

实测：**总差异 0.3835%，差异区域 bbox 恰好只是顶部那个视图切换按钮**；排除该区域后 **1,507,500 像素 100% 相同**。

> 结论一句话（可以直接讲给用户）：
> **HTML 和 Markdown 的区别是"内容的写法"，不是"长什么样"。CSS 才决定长相，换格式不动 CSS，就一个像素都不会变。**

## 2. HTML → Markdown 转换器

一次性的转换脚本就够，不需要通用库。要点：

| 环节 | 做法 |
|---|---|
| 取顶层块 | **手写深度计数器**，不要用正则。正则处理嵌套元素一定出错 |
| 行内转换 | 用哨兵字符 `\u0001` 保护 `<code>` / `<kbd>` 的内容，转完 `**` `*` `[]()` 再还原 |
| 代码块语言 | 按内容猜（`<`/`</x>` → html；`{`+`;` → css；`function`/`=>`/`document.` → js） |
| 卡片 | `<div class="card limit">` + `.card-tag` → 自定义围栏 `:::limit 局限 1 · 标题` … `:::` |
| 表格 | `| a | b |` + `| --- | --- |` 分隔行 |
| 断言 | 转换完打印"未识别的顶层块数"，**必须是 0** |

实测第 4 章：10326 字符 HTML → 5940 字符 Markdown，**0 个未识别块，10 个代码块全部带语言标记**。

### 自定义围栏语法

`:::type tag` 是 Markdown 的扩展，映射到书的卡片：

```markdown
:::limit 局限 1 · 写错一个字母，没有任何提示
正文…
:::
```

渲染成 `<div class="card limit"><span class="card-tag">局限 1 · …</span>…</div>`。
因为书的正文只依赖 **7 个自定义 class**（`card-tag` `num` `callout-num` `glyph` `sub` `c-st` `c-cm`），
卡片模板高度统一，所以这个映射是完备的。

## 3. 渲染器必须踩的坑

### 单遍扫描，不能先处理行内再处理块级

块级和行内是两种语法，嵌套起来正则替换会互相破坏。

### `**...**` 里的 `*` 会毁掉加粗

`data-*` 这种文本会出现在加粗内容里：

```js
// ✗ 错：遇到 data-* 的 * 就停止匹配，所有 ** 全部漏网
s = s.replace(/\*\*([^*]+)\*\*/g, "<strong>$1</strong>");
// ✓ 对：懒惰匹配，允许内容含 *
s = s.replace(/\*\*([\s\S]+?)\*\*/g, "<strong>$1</strong>");
```

定位方法就是 §1 的首尾公共前缀法 —— 它打印出 `data-是给JavaScript的钩子。**`（少了一个 `*`），一眼看出是加粗正则吃掉了字符。

## 4. 书架的三层结构（⚠️ 设计定稿，未落地）

```
shelf.html          索引层：书架，列出所有书 + 每本书的进度/旁注数
books/*.md          内容层：正文。新书写 .md；老书继续用 .html（"遗留书"）
notes/*.json        笔记层：旁注，独立于正文
```

**三层必须分离**。理由：正文是"书"，旁注是"你"，两者的生命周期完全不同 ——
书可以重写、可以换版本，你的旁注不该因此丢失。

## 5. 旁注（margin note）设计

### 用户的原话就是设计稿

> "我只是在读原来的文章，只是这篇文章里面有一点章节我没有懂，所以我**旁支了一个注释**。
> 这个注释可以是一篇很大的、可以上下滑动的文章。它可以是一个小气泡，也可以是一个大气泡，
> 但我还是在原来的文章里。"

命名：**旁注**。不是"在原文下面跟一条评论"，是**在原文旁边长出一个子空间**。
它同时是两件事：

- 作为**笔记**：你手写；
- 作为**解释**：让 AI 写（用户有 API key）。

**这两条需求是同一个机制的两面** —— 这是整个设计的关键洞察。

### 存法

```json
{
  "id": "B",
  "anchor": "这是一条必须记准的转换规则",   // 文字锚点
  "quote": "塞进一个属性。读的时候按",       // 若锚在词/句上
  "kind": "边界实测",
  "title": "data- 后面跟数字、跟大写字母，会变成什么",
  "where": "§4.2 ② data-* 的名字怎么变成 JS 里的名字",
  "mine": false,
  "body": "…markdown…",
  "refs": [{ "t": "MDN · HTMLElement.dataset", "u": "https://…" }]
}
```

### 文字锚定，不要位置索引

锚点存**"选中的文字 + 搜索它"**，不存"第几段第几个字符"。
这样"正文可编辑"和"笔记不错位"才能共存 —— 改一段话，只要那句话还在，旁注就还在。

落锚有两级粒度，都要支持（用户明确要的）：

| 粒度 | 触发方式 | 落锚位置 |
|---|---|---|
| 段落 | 段落左侧 hover 浮出圆点，点 `＋` | 段级 |
| 词 / 句 | **选中文字**，浮出"给「…」补旁注"按钮 | 文字级（`<mark class="mk-mark">`） |

文字级的视觉：选中产生的旁注把原文那几个字包进 `<mark>`，**黄色高亮 + 虚线底边**，
点它就再打开旁注。这是"锚在文字上而不是段落上"最直观的证明。

### AI 生成链路

1. 用户点击指定位置（**闸门**：必须先由用户指定"哪里没懂"，否则内容会被灌水）
2. 服务端拼上下文：**这一段 + 它的上文 + 这一章的小标题**
3. 用户勾选"允许联网"时，服务端先检索，把结果拼进上下文（**模型自己不能实时联网**，必须服务端做）
4. 模型写出一篇 Markdown 旁注 + 引用来源
5. 用户点"保存为旁注" → 落进 `notes/*.json`

**关键取舍：让 AI"从零写一段"比"改一段"轻得多。**
一次生成就能成稿，不需要 diff 应用、不需要冲突处理、不影响正文的正确性。
所以"AI 重写正文"要慎重，"AI 补旁注"可以放心做。

### 四个生命周期动作

| 动作 | 含义 |
|---|---|
| `promote` | 旁注晋升为正文（这是"讲得不够"的正式修正） |
| `demote` | 把正文里太深的一段降级成旁注 |
| `edit` / `delete` | 编辑 / 删除（删除留 7 天可恢复） |

`promote` / `demote` 让**读书笔记成了书的修订来源** —— 这是这个设计比"划线批注"强的地方。

### 旁注清单的额外价值

一张"你挂的 N 篇旁注"的清单，其实就是"**我在这本书里卡过的地方**"。
攒多了，一眼看出自己真正薄弱的是哪一类概念。

> **笔记记录你懂的东西，旁注记录你不懂的。**

## 6. 原型外壳的实现要点

| 要点 | 做法 |
|---|---|
| 圆点不引起重排 | 圆点 `position: absolute; left: -34px`，段落 `position: relative`。**不要用加边框的方式**，会让正文抖动 |
| 阅读区左侧留白 | `.mk-read { padding-left: 62px }` 给圆点让位 |
| 侧栏宽度 | 408px（正文 760px 时比例舒服）；`<980px` 断点改成上下堆叠 |
| 激活段高亮 | `.mk-active { background: rgba(246,204,63,.16); box-shadow: -4px 0 0 rgba(246,204,63,.5) }` |
| 选中文字浮按钮 | `read.addEventListener("mouseup")` → `setTimeout(…, 0)` 等选区稳定 → `getBoundingClientRect()` 定位 `position: fixed` 按钮 |
| 浮按钮不被自己的 mousedown 关掉 | 按钮自身 `mousedown` 里 `e.preventDefault()`，`document` 的关闭逻辑判 `floatBtn.contains(e.target)` |
| 旁注面板里的表格 | 表头加 `white-space: nowrap`，单元格用 `word-break: normal`。**不要 `word-break: break-word`**，会把 `dataset` 断成 `datase/t` |

### 一个容易忽略的绑定顺序坑

段落上的圆点如果**在绑定点击时就把 note 闭包进去**，之后新建的旁注点不开（闭包里还是 `null`）。
正确做法：点击时**从 DOM 现读** `el.getAttribute("data-note")`，需要时再 `openNote(id)`。
这样"新建旁注"只要 `setAttribute` + 改圆点文字就行，不用重绑。

## 7. V1 正式版的落地方案（用户验收后的定稿，2026-09）

上一节的方案经过用户验收后，有四处被推翻或固化，**做 V2 前先读这里**：

### 用户对视觉的裁决：黄底序号圆点被否了

原型的「黄底 + 数字圆点」用户原话"**太丑陋了**"。他只要知道"哪段话被我标了注释"。
定稿方案：

| 标记 | 样子 |
|---|---|
| 有旁注的段落 | 左侧 **2px 粘土色竖线**（`rgba(206,123,81,.32)`），hover 加深并浮出 5px 小圆点 |
| 词/句级锚点 | 那几个字带**虚线下划线**（不是底色！比高亮更克制），点字打开 |
| 晋升后的补充块 | 左 3px 粘土色边 + 5% 粘土色底 + 「补充」小圆标签 |
| 导航 | 右下角药丸「‹ 2/7 ›」+ ☰ 清单入口 |

识别色统一用**原书自己的 --clay**（不引入新颜色），情绪价值来自"和书是一套的"。

### 第二轮裁决：满高抽屉也被否了，改浮窗气泡（V1.1 定稿）

用户试用后："字太多""不要占整个侧边栏那么长条""要圆润""点注释要有从原地飞过去的动效""生成时让被圈的字模糊、有思考的动静"。落地定稿：

1. **砍字是第一原则**。气泡里不写"挂在 XX 这几个字上"这类说明——标题就是选中的字（`“连字符 + 小写”`），提问态只有一个输入框 + 一个「解释」按钮，查看态三个 ghost 小按钮（晋升为正文 / 改 / 删）。用户问"他要看的到底是你的字还是正文？"——**任何 UI 文字都要过这道题**。
2. **气泡**：392px 宽、内容自适应高、圆角 22px、`right:28px; top:96px` 悬浮、大阴影。不满屏。
3. **飞入动效（FLIP）**：气泡先放目标位 → 读目标 rect → 设初始 `transform: translate(点击点-目标点) scale(0.4)` + `opacity:0` → 强制 reflow → transition `transform .4s cubic-bezier(.2,.8,.2,1), opacity .26s`。**注意**：`style.transform` 永远读的是目标值（inline style 已被同步设为目标），验证动效必须读 `getComputedStyle` 的插值，且 `page.click` 自身耗时会吃掉动效前半段——要在 evaluate 里 click + rAF 逐帧抓。
4. **生成中的获得感**：选中的字临时包 `mark[data-note="__p__"]` 加 `filter: blur(1.6px)`（"正在被加工"）；气泡里**思考流**文字每 1.15s 换一条（"读懂你圈出的这句话 → 往回翻它所在的那一段 → …"）+ 三个粘土色呼吸点脉动。完成/关闭时必须还原（删临时 mark、clearInterval）。
5. 点击打开用**委托**（main 上 click → closest("mark.nb-quote") / closest(".nb-block")），把被点元素传给气泡当飞入起点。

### 书正文：保留原书 HTML，不转 Markdown

"好看"来自原书的 CSS 和排版。转 Markdown 是给"要编辑内容"的场景用的；
用户要的是"在原书基础上加一点点"，所以 build.mjs 直接从原书提取 `<style>` + body + 原脚本
拼出新 index.html（原书文件一字不动）。**旁注仍是 Markdown**（AI 生成的就是），在侧栏渲染。

### 晋升为正文：渲染时注入，不改原书

`promoted: true` 存在旁注数据里，加载时把旁注内容渲染成「补充」块**插到锚点段落后面**。
好处：原书永远不动、随时可撤（demote = 取消标记）、刷新自动恢复。
比"真把内容写进书文件"安全一个量级。

### AI 接入（接 MiniMax 的实测配方）

- key 从 `~/.workbuddy/models.json` 读，**只在本地 Node 服务端**，前端只调同源 `/api/explain`（密钥不进前端的完整论证见 `local-webapp-llm-integration` skill，两份配方配合用）
- `reasoning_split: true` 让 content 只留答案（M2.5 实测有效），**仍要客户端 stripThinking 兜底**
- temperature 0.6；旁注这种短文 max_tokens 4000 够；ECONNRESET 重试 3 次
- **提示词必须有一条比喻约束**：实测 M2.5 会为了生动编造错误比喻（把 camelCase 说成"长颈鹿"）。
  加「比喻要贴切；宁可平实准确，也不要为了生动用牵强或错误的比喻」+ 降温后消失

### 自动化测试的三个坑

1. 教学书常有 `html { scroll-behavior: smooth }` —— 脚本里 `window.scrollTo(0, y)` 变平滑滚动，
   **立即读 scrollY 还是 0、rect 不变**。测试必须 `behavior: "instant"`。
2. 选区不在视口内时 `getBoundingClientRect()` 给出文档级大坐标（如 21190px），
   浮出按钮会定位到屏幕外。必须 clamp：`r.bottom < 0 || r.top > innerHeight` 时直接不显示。
3. 杀端口用 `lsof -ti :PORT -sTCP:LISTEN`（不带 `-sTCP:LISTEN` 会把已建立的连接也算进去，kill 报 illegal pid）。
